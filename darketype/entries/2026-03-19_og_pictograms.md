# every entry gets a face

sharing a darketype entry on Twitter, Discord, or Slack used to produce the same generic preview every time — the site-wide `darketype-og.png`, a title that just said "darketype // weblog," and a description about "failures and semi-successes." every link looked identical. you couldn't tell which entry someone was sharing without clicking through. crawlers don't execute JavaScript, and `entry.html` was a client-side SPA with hardcoded `<meta>` tags, so they all saw the same thing.

now every entry has its own face.

### the architecture

two new build steps bolt onto the existing `build_weblog.js` pipeline:

**static HTML pages** — for each entry, a `darketype/weblog/{slug}.html` file is generated by cloning `entry.html` with rewritten `<meta>` tags. the `og:title` becomes the entry title. the `og:image` points to a slug-specific PNG. the `og:url` points to the static page. paths are adjusted for the weblog subdirectory (`../css/style.css`, `../../assets/favicons/weblog.svg`). the JavaScript entry loader gets its query-param logic replaced with a hardcoded path to the correct markdown file. everything else — marked.js, DOMPurify, Viewer.js, tweet embeds, viscous.js — works unchanged.

**programmatic OG images** — `scripts/generate_og_images.js` uses `node-canvas` to render a 1200x630 PNG per entry. the images maintain the CRT aesthetic: `#0a0a0a` background, scanlines every 3px, pixel grid noise at the edges, radial vignette, rounded CRT bezel, and state-dependent glitch stripes. title text renders with chromatic aberration (red layer offset -Npx, blue +Npx, green primary at origin). metadata line and branding sit below in dim green.

### the pictograms

the part that makes each image actually identifiable: a content-relevant silhouette drawn on the right side of the frame.

a keyword matcher reads each entry's title and tags, then selects from a library of 17 programmatic pictograms:

| pictogram | triggers | visual |
|-----------|----------|--------|
| `dataLeak` | cslp, leakage, leaking | pixel grid with dripping data lines |
| `compass` | origin, manifesto | compass rose with cardinal diamonds |
| `blackHole` | singularity, event horizon, physics | distortion rings with accretion particles |
| `infinityLoop` | loop | figure-eight with directional arrows |
| `magnifyingGlass` | autopsy, audit, gamedev | lens with circuit traces inside |
| `spotlight` | ted, stage, optimism | cone of light, podium, figure silhouette |
| `fractalTree` | chaos, fractal | recursive branching tree (7 depth levels) |
| `gears` | logo, factory | interlocking gear outlines |
| `maze` | maze, ktane, kahn | procedural grid maze with entry/exit dots |
| `anchor` | ocean, port + disaster | nautical anchor with curved flukes |
| `tarotCard` | runbook, tarot, diagnostic | rounded card with eye symbol and corner marks |
| `floatingBlocks` | antigravity, automation | isometric cubes at varying heights with motion lines |
| `portal` | daemon, summon, metaverse | concentric energy rings with horned silhouette |
| `shield` | pushes back, scorecard | shield outline with deflecting arrows |
| `neuralNet` | vertex, neural, repoptic | three-layer node graph with weighted edges |
| `fingerprint` | viscous, lcd, finger | fingerprint arcs with LCD ripple rings |
| `eye` | widget, context-awareness, woke | almond eye with iris, pupil, and awareness rays |
| `prism` | per-char, chromatic, bruise | triangular prism splitting light into RGB beams |
| `lake` | context + lake | rippling water surface with submerged data nodes |
| `flag` | rebellion, phase zero | waving flag with "0" on pole |
| `terminal` | (fallback) | terminal window with prompt lines |

each pictogram is drawn three times with chromatic offsets (red, blue, green layers) at reduced opacity, so they feel like ghosted CRT afterimages rather than solid graphics. state-dependent configs control the chromatic offset distance and glitch stripe intensity — `mess`/`broken` entries get heavier distortion, `shipped` entries are clean, `void`/`seed` entries are extra dim.

### deterministic randomness

all procedural elements — pixel noise density, maze wall placement, glitch stripe positions — use a seeded PRNG (mulberry32) initialized from the entry's epoch timestamp. builds are fully reproducible. the same entry always generates the same image.

### incremental builds

the generator skips entries where `assets/social/og/{slug}.png` already exists. pass `--force` to regenerate all. this keeps the build fast as the entry count grows — new entries generate in under a second, the full set of 21 entries takes ~3 seconds.

### the build pipeline

```
npm run build
```

runs `build_weblog.js` then `generate_og_images.js` in sequence. the weblog script produces `entries.json` (now with `slug` and `description` fields), updates `weblog/index.html`, generates `heatmap.json`, and writes static HTML pages. the OG script reads `entries.json` and renders the images.

the `/entry` workflow in `.agent/workflows/entry.md` calls `npm run build` and stages `darketype/weblog/` and `assets/social/og/` alongside the existing entry files.

### backwards compatibility

`entry.html` is untouched. old `entry.html?log=entries/...` links continue to work — they just show generic OG tags when shared. new `weblog/{slug}.html` links get the full treatment. `entries.json` gained two fields (`slug`, `description`) but retains all existing ones. the weblog index's `syncEntries()` function uses `entry.path` for link hrefs, which now points to `{slug}.html` within the same directory.

### the template

`darketype/entries/TEMPLATE.md` now includes an optional `og_image` frontmatter field. leave it blank for the auto-generated pictogram image. set it to a path for manual override.

### what it looks like

the "daemon summons" entry gets concentric portal rings with a horned silhouette. "data points for what not to do (Kahn and KTANE)" gets a procedural maze. "the context lake" gets rippling water with data nodes sinking below the surface. "every letter has its own bruise" gets a prism splitting light into RGB beams with scattered letters.

each image is visually distinct at thumbnail size. you can tell which entry someone shared without reading the title.
